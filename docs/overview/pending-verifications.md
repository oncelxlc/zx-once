# 待操作验证清单

后续尚未验证的操作及预期结果统一记录在此，待用户确认后集中验证。[操作验证约定](../../AGENTS.md#操作验证)

无界面 Chrome 已在 1280 × 720 浅色、1440 × 560 深色、390 × 640 深色和 320 × 580 浅色视口检查 11 个页面入口。44 组检查均确认页头紧贴客户区顶部，网页版三个导航按钮位于底部状态栏。22 组长页面实际滚动后，页头和导航的位置保持稳定。已通过实际哈希路由验证前进、返回、分支清除、快捷键及输入框焦点保护。

Windows 11 Build 26300 的独立测试实例中，原生标题栏背景采样为浅色 `#F0F2F4`、深色 `#1D1D1D`，与工作台侧栏和状态栏的主题色对应。已检查窗口标题、图标、系统菜单、系统按钮命中区和缩放边缘，并验证最小化、最大化、还原、标题栏双击及双显示器移动。

在同一桌面的实际窗口中，三个导航按钮位于应用名称和系统按钮之间，底边与 WebView 上沿重合。逐项点击只触发对应操作；禁用按钮点击不触发事件，悬停仍显示提示。菜单在两种状态下分别提示「展开导航」「收起导航」，切换时窗口保持原位。已用鼠标和 `Alt+←/→` 验证主页面、子页面及返回后的新分支；在项目搜索框中按快捷键保持当前页面。MSAA 可读取三个按钮的中文名称。

在普通桌面已通过鼠标拖动和边缘缩放、`Win+←` 贴靠、`Alt+F4` 关闭及托盘重建测试。重建后的窗口恢复深色标题栏。WebView2 请求全屏时，原生装饰消失，窗口铺满 2560 × 1440 显示器；退出后装饰和客户区高度恢复。主窗口使用 Per-Monitor V2，两台实测显示器均为 96 DPI。

标题栏导航按钮在最大化和跨屏后随窗口重新定位；最小化和全屏时隐藏，还原后重新显示。其他应用覆盖主窗口时，导航按钮也被遮挡。从托盘重建主窗口后，两个历史按钮按新窗口的初始历史禁用。

在 Windows 11 上实际悬停系统最大化按钮，Explorer 显示 364 × 264 像素的 Snap Layouts 浮层。选择双列布局的左半区后，窗口贴靠左侧，三个导航按钮随窗口移动，底边仍与客户区上沿对齐。

在独立灵动岛配置中调用显示、隐藏命令，原生岛窗可见性均随命令变化。关闭主窗口期间岛窗与托盘继续运行，托盘重建主窗口后，岛体仍为启用、收起状态。

- [ ] 在 Windows 桌面查看总览的六张默认卡片，确认按列连续排列。
- [ ] 在 Windows 10 及 Windows 高对比度环境中检查标题文字与原生按钮。在缩放比例不同的显示器间拖动窗口，检查标题栏、窗口按钮和页面缩放。
- [ ] 在 Windows WebView 中悬停及用键盘聚焦收起的侧栏图标，检查提示位置、组间短线居中和底部设置入口。用标题栏导航开关在侧栏动画中途反向切换，检查分组标题和图标过渡。
- [ ] 在低高度窗口分别用滚轮滚动两级导航，检查设置入口和当前分组的可见性。窄屏浏览器中用触控打开主导航抽屉、横向浏览二级导航，并到达长表单的底部。
- [ ] 分别在主窗口打开和已关闭至托盘时，点击 Windows 托盘菜单「灵动岛设置」，确认两种情况下都能打开灵动岛设置页。
- [ ] 在灵动岛「动画效果」分组修改一项设置，保留未保存的草稿并关闭主窗口。从托盘点击「打开主界面」，确认恢复该分组和草稿。
