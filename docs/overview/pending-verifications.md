# 待操作验证清单

后续尚未验证的操作及预期结果统一记录在此，待用户确认后集中验证。[操作验证约定](../../AGENTS.md#操作验证)

调整圆角布局前，无界面 Chrome 已在 1280 × 720 浅色、1440 × 560 深色、390 × 640 深色和 320 × 580 浅色视口检查 11 个页面入口。44 组检查均确认网页版三个导航按钮位于底部状态栏。22 组长页面实际滚动后，页头和导航的位置保持稳定。已通过实际哈希路由验证前进、返回、分支清除、快捷键及输入框焦点保护。

调整后，Windows 实窗的浅色和深色总览均可辨认圆角主内容区、侧栏、状态栏和卡片。Chrome 截图像素确认主内容区四角半径为 14px。六张默认卡片在 1440 × 880、1280 × 720 视口排成两列，在 390 × 640、320 × 580 排成一列，均无页面横向溢出。

改用垂直二级菜单前，在 1280 × 310 的 Chrome 窗口分别对一级、二级导航滚轮滚动，各自滚动了 330px、106px，底部「设置」入口仍可点击。在 390 × 640 视口模拟触控，已打开主导航抽屉、横向滑动旧二级导航 216px，并将外观表单滚至底部。Chrome 模拟强制颜色模式时，三个导航按钮的 Tab 焦点曾不可见，修复后截图可见 2px 系统高亮色轮廓。

Windows 11 Build 26300 的独立测试实例中，原生标题栏背景采样为浅色 `#F0F2F4`、深色 `#1D1D1D`，与工作台侧栏和状态栏的主题色对应。已检查窗口标题、图标、系统菜单、系统按钮命中区和缩放边缘，并验证最小化、最大化、还原、标题栏双击及双显示器移动。

调整导航按钮尺寸前，已在同一桌面验证三个按钮位于应用名称和系统按钮之间。逐项点击只触发对应操作；禁用按钮点击不触发事件，悬停仍显示提示。菜单在两种状态下分别提示「展开导航」「收起导航」，切换时窗口保持原位。已用鼠标和 `Alt+←/→` 验证主页面、子页面及返回后的新分支；在项目搜索框中按快捷键保持当前页面。MSAA 可读取三个按钮的中文名称。

调整后，在隐藏的 Windows 原生工具栏上测得 32px 按钮宽度、3px 间距，并核对了三个按钮的命中索引与侧栏选中状态。GDI 离屏绘制覆盖浅色、深色和 100%、125%、150%、200% 四档缩放，已检查默认、悬停、选中、按下和禁用状态的图标及背景像素。

Windows 实窗中，前进和返回按钮随历史记录切换可用状态。展开侧栏后移走鼠标，开关保留选中底色，收起后恢复透明。拖动相邻标题栏空白，主窗口和工具栏一起向右移动 85px、向下移动 45px。收起状态下，鼠标悬停「项目」、用 Tab 聚焦「Git 工作区」均在对应图标旁显示提示，底部「设置」可用。实窗连续快速点击开关后回到初始布局；Chrome 中在动画约 60ms、侧栏宽约 109.4px 时反向切换，最终收回至 52px。

在普通桌面已通过鼠标拖动和边缘缩放、`Win+←` 贴靠、`Alt+F4` 关闭及托盘重建测试。重建后的窗口恢复深色标题栏。WebView2 请求全屏时，原生装饰消失，窗口铺满 2560 × 1440 显示器；退出后装饰和客户区高度恢复。主窗口使用 Per-Monitor V2，两台实测显示器均为 96 DPI。

标题栏导航按钮在最大化和跨屏后随窗口重新定位；最小化和全屏时隐藏，还原后重新显示。其他应用覆盖主窗口时，导航按钮也被遮挡。从托盘重建主窗口后，两个历史按钮按新窗口的初始历史禁用。

在 Windows 11 上实际悬停系统最大化按钮，Explorer 显示 364 × 264 像素的 Snap Layouts 浮层。选择双列布局的左半区后，窗口贴靠左侧，三个导航按钮随窗口移动，底边仍与客户区上沿对齐。

在独立灵动岛配置中调用显示、隐藏命令，原生岛窗可见性均随命令变化。关闭主窗口期间岛窗与托盘继续运行，托盘重建主窗口后，岛体仍为启用、收起状态。

此次在 Windows 11 Build 26300 上逐项运行了默认跳过的四个 Rust 实机测试，全部通过。测试从开始菜单标识识别已安装的微信与 QQ，两次注册并释放全屏监听钩子，在同一 HWND 上重建 D3D11 渲染设备，并验证两种岛体形状在两台显示器顶部、左侧和右侧的全部 12 组拖动停靠组合。两台显示器的有效 DPI 均为 96。

在实际 Windows 标题栏上，三个按钮都捕获到鼠标按住与原生按下状态同时生效的帧。浅色按下底色为 `#CACDD0`，圆角顶点为 `#F0F2F4`；深色分别为 `#404040` 和 `#1D1D1D`。悬停底色实测为浅色 `#DFE1E4`、深色 `#2C2C2C`。实窗读到了「返回」「展开导航」，禁用的前进箭头也显示「前进」提示。

在使用独立配置与 WebView 数据目录的测试实例中，从实际 Win32 托盘菜单读取命令 ID 并分发。主窗口打开时，「灵动岛设置」从普通设置页切到灵动岛；从总览关闭主窗口后，同一命令新建窗口并进入 `#/island`。在「动画效果」把展开时长从 300 改为 417 毫秒后关闭窗口，「打开主界面」恢复到 `#/island?group=animation`，字段仍为 417，页面仍提示「有未保存的更改」。该检查经过原生菜单命令处理和真实窗口销毁、重建。

合并外框设置前，使用生产 CSS 在无头 Chrome 中逐项比较页头、侧栏、底栏与正文在两种底色上的像素。浅、深主题下共检查了 48 对采样。

统一外框后，无头 Chrome 用生产 CSS 核对了浅、深主题在 0%、65%、100% 透明度下的像素，覆盖浏览器、模拟原生材质及不可用回退，共 18 组。每组中侧栏、底栏、外边距和圆角外留白的采样值一致，页头和正文均为该主题的页面底色。

隐藏的 Windows 主窗口样本接收失焦绘制消息后，系统读回的标题栏状态仍为活动样式，窗口未获得前台焦点。解除固定外观后，同一消息恢复系统的非活动绘制状态。

隐藏的 Win32 工具栏也已通过像素测试。默认状态下，按钮空白处的最终 alpha 为 1/255，箭头笔画为 255/255。选中底色的遮罩值为 30/255，禁用箭头为 102/255。测试走实际工具栏绘制通知和分层窗口更新，并检查了切回实色的路径。

无头 Edge 使用生产样式测量了侧栏收起、展开及中途反向切换时的布局。在 224px 到 52px 之间的全部采样点，导航项和底部「设置」的图标中心都距侧栏左边缘 26px，文字透明度随收起降至 0，随展开恢复到 1。

设置页在 320px、390px 的无头 Edge 视口中为单列，未出现横向溢出。1280px 和 1440px 下收起主导航时，工作台外观、导航分组和灵动岛字段均排为两列。1920px 时导航分组排为三列。1280px 下展开主导航后，导航分组随正文变窄回到单列。灵动岛预览占满表单一行。
